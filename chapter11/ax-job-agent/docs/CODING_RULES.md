## 규칙 001. 노트북 3단 작업 단위 (필수)

**모든 코드는 아래 3개를 하나의 단위로 묶어서 작성한다. 예외 없음.**

```
1. [Markdown] 작업 계획
   - 이번 셀(들)에서 무엇을 확인/구현하는지
   - 완료 조건은 무엇인지

2. [Code] 실제 코드
   - 이번 단위에 필요한 최소한의 코드만

3. [Markdown] 실행 결과 해석
   - 성공 여부:
   - 확인한 데이터/수치:
   - 예상과 다른 부분:
   - 다음 단계 진행 가능 여부:
   - 추가 확인 사항:
```

**금지 사항:**
- 3번(결과 해석) 없이 다음 작업으로 넘어가지 않는다.
- 여러 STEP의 코드를 한 번에 몰아서 작성하지 않는다 (STEP 하나 = 이 3단 단위 최소 1세트).
- "실행이 성공했다"와 "결과가 올바르다"를 같은 것으로 쓰지 않는다 — 2번이 에러 없이 돌아도 3번에서 반드시 숫자/내용을 실제로 확인하고 적는다.

**Claude Code에 작업 요청할 때 이 표현을 포함시킬 것:**
> "Markdown(계획) → Code(실행) → Markdown(결과 해석) 3단 패턴으로 작성해줘. 결과 해석 셀은 빈 템플릿이 아니라 실제 실행 결과를 채워서 작성해줘."

| 문서 | 바뀌는 빈도 | 내용 |
|---|---|---|
| `PROJECT_SPEC.md` | 거의 안 바뀜 | 목표, 데이터 명세, 폴더 구조, STEP 목록, 원칙 |
| `PROGRESS.md` | 매 작업마다 | 지금 어디까지 했는지, 다음 할 일 |
| `CODING_RULES.md` (이 문서) | 규칙이 새로 생길 때마다 | 노트북 작성 패턴, 코딩 컨벤션 |
